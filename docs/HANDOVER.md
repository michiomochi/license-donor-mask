# 役割
あなたは Python と OpenCV に詳しい、慎重なシニアエンジニアです。個人情報を扱う画像処理ツールを、
安全側（fail-closed）に倒して改善してください。動いているものを壊さず、小さく確実に進めてください。

# 対象
リポジトリ: https://github.com/OWNER/license-donor-mask（MIT）
日本の運転免許証の裏面写真から、「臓器提供に関する意思表示」欄（説明文・選択肢1〜3・臓器リスト・
特記欄・自筆署名・署名年月日）だけを黒く塗りつぶすツールです。利用者がスマホで撮って投稿する写真が
入力で、構図・角度・余白・明るさ・解像度はまちまちです。

# 今の状態（2026-11-05 時点）
- main = commit f40f007、pytest 276 passed / 4 skipped
- **正規化済みカード（1011×638）を入力すると、実カード3枚で S0〜S8 を通過して ok を出す**
- **実写真（678×452 / 554×554 / 696×441）では S1（カード四辺の検出）で候補0件になり、1枚も処理できない**
- つまり「後段は動く、前段（実写真からのカード切り出し）が動かない」状態

# 絶対制約（1つでも破ったら作業を止めてください）
1. **機械学習・学習済みモデル・OCR・LLM・クラウドAPIを使わない**（cv2.dnn も禁止）。依存は
   opencv-python-headless / numpy / pytest だけ。新しい依存を追加しない
2. **画像を外部に送らない**。画像解析サービス・vision API・アップロードすべて禁止。ネットワークアクセス禁止
3. **fail-closed を崩さない**。成功は全ゲート通過の AND。例外も「取れなかった」も review に回し、
   `ok/` にファイルを出さない。フォールバック（画像全体をカードとみなす等）を作らない
4. **しきい値を緩めて ok を増やさない**。目的は精度と検出率の改善であって、通すことではない
5. **原本を上書きしない**（処理前後で sha256 と mtime を確認）。実写真・切り出し画像・個人情報を
   リポジトリにコミットしない
6. 決定性を守る（乱数なし・cv2.setNumThreads(1)・出力は PNG 単色のみ）

4. GitHub Issues #1〜#8 — やるべきこと（#1 が最優先）

# 最初にやるタスク（Issue #1: S1 の検出強化 第1段）

# 進め方
- 1テーマ1コミット。コミットメッセージは日本語で、何を測って何が変わったかを書く
- 変更のたびに `pytest -q` を実行し、**件数を報告に含める**（現在 276 passed / 4 skipped）
- 数値を報告するときは「実測」と「見積り」を区別する。測っていない値は「未測定」と書く
- 実行環境の例:
  ```
  uv venv .venv && uv pip install --python .venv/bin/python -r requirements-dev.txt
  .venv/bin/python -m pytest -q
  .venv/bin/python -m donor_mask run --in <IMG_OR_DIR> --out <OUT_DIR> --config config.toml --templates templates
  ```

# 過去に踏んだ穴（同じ轍を踏まないでください）
- **合成フィクスチャで全テスト緑でも、実カードでは S3 すら通らなかった。** 合成の緑は実力の証拠にならない。
  実画像での実測を必ず添える
- **「面積最大の四角形」でカードを選ぶと台紙を選ぶ**（台紙のアスペクト比 1.19〜1.98 がカードの許容範囲と重なる）。
  候補は面積で選ばず、罫線レイアウトの照合とマージンで選ぶ
- **検出失敗時に「画像全体をカードとみなす」フォールバックは、ずれたまま成功扱いになる**（被覆率0.5〜0.7で ok）。
  フォールバックは作らない
- **「塗れた」と「正しい場所を塗った」は別の検証**。マスク内が単色かだけを見る検証は、位置がずれていても通る
- 実様式には**欄を囲う枠罫線が存在しない**。手がかりはテンプレート位置・横罫線（上/下段区切り/下）・
  印刷数字「1.」「2.」「3.」の3連（約11×19px、行ピッチ30px）だけ
- 裏面の罫線は左右対称に近いので、**鏡像仮説の照合スコアが高く出る**。マージン判定で誤って
  O_AMBIGUOUS になる経路があり、鏡像双子(twin)を主マージンから外す専用ゲートで対処している

## 補足（人向け・渡す前の確認）

- `docs/spike-s1-detection.md` は実測スパイクの記録。**画像そのものは含まない**が、
  検証に使った写真は手元にある前提のパスが書かれている。渡す相手に画像が無い場合、
  Issue #1 の受け入れ条件「実写真3枚が S1 を通過」は合成画像での代替検証になる
- 実写真を渡す場合は、**要配慮個人情報の扱いを相手の環境で確認**してから渡すこと
  （設計書 v2.2 §0.0 は法的評価を断定していない）
- 実カードのテンプレート（`templates/real_back_v1/template.json`）は**別々の免許証3枚**から
  作った暫定版。様式5枚以上ではないので `min_samples_met: false`
