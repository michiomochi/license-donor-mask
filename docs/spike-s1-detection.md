## 3. 手法ごとの所見（失敗理由の分析）

**現行 S1 の再現**: `donor_mask.card.find_candidates` を read-only import（bytecode 無し）で実行し、依頼の失敗を再現（img1: C_ASPECT×5-6 + C_PERSPECTIVE/C_AREA、img2: C_TOUCHES_BORDER×2、img3: C_ANGLE×3 + C_NOT_QUAD）。
- 倍率 1.5/2/3 に上げても 0/3 のまま（却下コードが入れ替わるだけ）。→ **手法1（解像度の適応化）単独は効かない。**
- 幾何閾値だけ緩和（面積0.10–0.99、角55–125°、対辺比≤1.8、アスペクト±40%、エッジ支持≥0.5、端マージン0、合意マップ数1）すると **img3 が 1.0倍で NCC 0.98**（strict）。img1/img2 は候補0のまま。→ **img3 型（有色カード＋木目）の失敗は閾値の厳しさが原因**。ただし緩めると偽陽性の余地が増える（S2/S3 の選別が前提）。

**手法1 解像度（Lanczos 1.5/2/3倍）**: 効果は**非単調**。Hough は img3 で 1.0倍✓/1.5倍✗/2倍✗/3倍✓、img2 で 1.0✓/1.5✓/2.0 辛うじて(0.52)/3.0✓。輪郭は img1 が 2倍でのみ 0.57（1倍 0.36、3倍 0.50）。**単一倍率に固定する根拠は無く、倍率を振った候補のプールにすると安定する**（表3: 12ケースで contour+hough = 10/12 → +テンプレで 12/12）。

**手法2 Hough（HoughLinesP→線分を角度/距離でクラスタ→辺ペア×辺ペアの交点で四隅。近似多角形に非依存。水平/垂直±45°固定ではなく「ほぼ平行なペア2組が50°以上で交差」に一般化）**: img2/img3 は 1.0倍と3倍で strict（0.87–0.89）。**img1 は原理的に不可**: 正解の3辺（上・左・右）から最も近い検出直線までが 27〜35px（1倍）離れていて、辺そのものに勾配が無い（下辺だけ 0.2px で取れる）。正解辺の長さ順位は 10〜30 位なので、直線の採用数を 16→36 に増やさないと img3 が出ない（組合せ探索が重くなる）。0.2–1.4 s/枚（Python）。

**手法3 色セグメンテーション**: dE_center（中央25%の中央値色からの ΔE → Otsu）が最良だが 3倍でも img2 0.72 / img3 0.62。**IoU は 0.95–0.99 まで出るのに NCC が 0.4–0.7 止まり**＝輪郭が数 px ふくらむ（ぼけた外縁）ので“粗い当たり”にはなるが単独では精度不足。k-means・GrabCut は倍率で結果が暴れる（GrabCut は 1.2〜6 s と遅い）。**img1 は dE_center 候補0、GrabCut/テクスチャ（手法3の範囲外の追加実験）は NCC 0.05–0.24 の誤検出**。→ 白on白は色/テクスチャでは分離できない（ΔE 6.6）。

**手法4 テンプレ照合掃引（回転×スケール[×せん断×縦横比]の matchTemplate → ECC アフィン→ホモグラフィ。DoG 表現で照明差を吸収）**:
- 他2枚から作ったテンプレ(LOO)で **img1 が通る唯一の手法（NCC 0.65, 角ずれ 1.3% 対角, 約 2 s）**。自分自身をテンプレにすると 0.97（上限）。→ 白on白はインク/罫線の“中身”で位置合わせするしかない。
- **img3 は通らない**（自己テンプレでも 0.31）。強い遠近で相似+せん断+縦横比のアフィン近似でも粗探索のピークを外す。せん断/縦横比格子を足す構成 B は 14–18 s/枚に膨らんだうえ **img2 が悪化(0.13)**（偽ピークが正解より高得点）。→ **構成 A（相似のみ・約 3 s/枚）で十分、B は不採用**。
- LOO テンプレの質: 整列後 DoG-NCC は 3枚間で 0.5–0.8（img3 は他と 0.53–0.70）。様式が共通でも個人情報欄が違うぶんピークは鈍い。

**手法5 組合せ（表3）**:
- 検証スコア V = warp 後の DoG 表現と LOO テンプレの NCC（巡回4向き最大）。**選択された候補の V は、誤り候補（正解NCC<0.5）の最大 V を全12ケースで上回った**（余白: img1 0.18–0.57 / img3 0.21–0.34 / **img2 は 0.10–0.14 と薄い**）。ただし「正しい候補の最小 V」が「誤り候補の最大 V」を下回るケースも多く（例 img1: 正解側最小 0.59 vs 誤り側最大 0.64–0.73）、**V は閾値で合否を切る用途には使えない（相対比較でのみ有効）**。
- **辺 polish（法線方向の最大段差に Huber 直線フィット）は不安定**: orig では 0.65→0.81 のように効くが、劣化画像で 0.65→0.39 と悪化する例あり（表3: 12/12 → 11/12）。**既定では入れない**。ECC(LOO) での詰めも img2/img3 で悪化（0.87→0.46, 0.89→0.13）＝LOO テンプレは“粗い当たりの検証用”で精密化には使えない。精密化は既存 S4（空欄カード ECC）に任せるのが筋。

## 4. 実行時間（Python 単スレッド, 1枚, 28コア機だが並列化なし）
輪郭 0.1–0.2 s（3倍率計）/ Hough 1.4–3.5 s（3倍率計）/ dE_center 0.13 s / k-means 0.15 s / **GrabCut 2.4–6.1 s（3倍率計）** / テンプレ粗+ECC 1.2–2.4 s / 検証 0.2–0.5 s。ALL = 6.0〜11.5 s。**GrabCut と k-means を外した構成（contour+hough+dE+tmpl）でも 12/12・strict 数も同じ**なので、実質 **約 3–6 s/枚**。

## 5. それでも通らない/怪しいケース（断言）
1. **白on白で四辺に勾配が無く、かつ印刷内容が薄い/テンプレと違う面**: 唯一の経路がテンプレ照合で、精度は NCC≈0.65 止まり。テンプレに無い様式（表面など）は V が使えず**検出不能**（negative テンプレとの判別は未検証）。
2. **強い遠近（img3 型：対辺比 1.2 前後＋左右辺の角度差 18°）で、かつ低コントラスト**: 相似/アフィンのテンプレ掃引は外す。img3 は有色カード＋明確な縁があるから輪郭/Hough で救えているだけ。白on白＋強遠近の組合せは3枚に無く**未検証（おそらく通らない）**。
3. **指/手が2辺以上を覆う＋カードが低コントラスト**: 色・輪郭は手を巻き込む（img2 の輪郭は IoU 0.9 でも NCC 0.13）。Hough とテンプレは通るが V の余白が最も薄い(0.10)ので、手の写り方次第で別候補に負ける恐れ。
4. **ぼけ強+縮小（0.5×+σ1）**: strict が落ちる（img1 は hit 止まり、polish すると 0.39 に悪化）。
5. **n=3 の過学習**: Hough/輪郭/DoG のパラメータはこの3枚を見ながら決めた。保留テストは劣化変種（同じ3枚の派生）のみで、**独立な新規写真での検証は未実施**。12/12 は“独立12回”ではない（実質3枚×劣化）。

## 6. 実装の価値・採用・工数
- **価値: ある（段階導入）。** 失敗3/3 のうち (a) img3 型は閾値緩和だけで解消、(b) img2 型は Hough 候補生成で解消（strict）、(c) img1 型はテンプレ掃引でのみ“hit”に到達。これらを揃えると本実験では 3/3。
- **採用順（費用対効果）**（工数は見積りであり実測ではない）:
  1. S1 の幾何条件緩和（最小変更）。選別は既存 S2/S3 に委ね `max_candidates` を監視。0.5〜1 日（回帰テスト含む）。
  2. 倍率プール（1/2/3）＋緩和輪郭＋Hough 候補生成器の追加。2〜3 日（辺選択の組合せ爆発対策・時間予算・テスト）。
  3. テンプレ相似掃引+ECC を低コントラスト用候補生成器として追加（既存 S2 署名/S4 ECC と共通化できる部分が多い）。2〜3 日。
  4. 独立な実写真（目安10枚以上、白on白・手持ち・遠近・暗所）で閾値校正。1〜2 日（撮影/GT 作成別）。
  合計の目安 1〜1.5 週間。
- **不採用**: GrabCut（遅い・不安定）、k-means（倍率で暴れる）、テクスチャ分離（img1 でも NCC 0.05）、せん断/縦横比格子のテンプレ掃引（遅い・img2 悪化）、辺 polish と LOO-ECC 精密化（劣化時に悪化）。
- **採用手法の断言**: 「**緩和S1 ＋ 多倍率(1/2/3)の輪郭・Hough 候補 ＋ テンプレ相似掃引→ECC 候補 → 既存 S2/S3 で選別 → 既存 S4 で精密化**」。解像度適応化は“単独の対策”ではなく“候補プールを広げる手段”として使う。
