# license-donor-mask

運転免許証の**裏面**の写真から、「臓器提供に関する意思表示」欄を**黒く塗りつぶす**ツールです。

- 画像をインターネットに送りません。AI・OCR・学習モデルも使いません（OpenCV の決まった処理だけ）。
- 自信がないときは**塗らずに「人の確認待ち（review）」に回します**。誤って塗り残したまま「成功」にはしません。
- 写真は、免許証が画像の中央に写り、多少傾いていたり背景があってもかまいません。画像ごとの調整は要りません。

> **状態**: 参考実装です。手元のテスト画像 9 枚（免許証 7 枚）でしか確かめていません。**実際の申込書類の写真での精度は未確認**です。本番では、まず少量で動かし、下の「結果の見方」の集計を見てから広げてください。

## 3 ステップで使う

### 1. 準備（初回だけ）

Python 3.11 以上が必要です。

```bash
python3.11 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
```

### 2. 実行

写真を 1 つのフォルダ（jpg / jpeg / png）に入れて、次を実行します。

```bash
python -m donor_mask run --in ./inbox --out ./out --config config.tolerant.toml
```

- `--in`: 写真のフォルダ（ファイル 1 つでも可）。**元の写真は変更しません。**
- `--out`: 結果の出力先。`--in` と同じフォルダや、その中は指定できません。
- `--config`: 設定ファイル。迷ったら下の表のとおり `config.tolerant.toml` を使います。

### 3. 結果を見る

```
out/ok/xxxx__masked.png       塗れた画像（これが成果物。PNG）
out/ok/xxxx__preview.jpg      確認用（塗った枠を赤、カードの四辺を緑で重ねたもの）
out/review/xxxx__review.jpg   塗れなかった画像に理由を重ねたもの（欄の中身が見えるので取扱注意）
out/logs/xxxx.json            1 件ごとの記録（数値だけ。画像の中身は入らない）
```

- `ok/` の画像だけを次の工程に渡します。`review/` の画像は、人が確認して手で処理するか、撮り直しを依頼します。
- ファイル名は元のファイル名ではなく、画像から作った 16 桁の ID です（氏名が名前に入っていても出力に残らないようにするため）。
- 終了コード: `0` = 全件 ok / `3` = review が 1 件以上 / `1` = 設定や入出力の致命的なエラー。

## 設定ファイルの選び方

| 使いたい場面 | `--config` | 特徴 |
| --- | --- | --- |
| 厳密に運用する（迷ったら review） | 指定なし（`config.toml`） | 手元の免許証 7 枚のうち ok は 1 枚。review が多い |
| 黒塗りの位置が多少ずれてもよい（推奨） | `config.tolerant.toml` | 手元の免許証 7 枚すべて ok。免許証でない画像は review のまま |

- `tolerant` でも、**個人情報を塗り残したままの画像は ok にしません**。緩めているのは、塗りが欄からはみ出す・カードの縁にかかるといった「塗りすぎ・ずれ」の側だけです。
- 他の `config.*.toml`（`m3` `relaxed` `refine` `sift`）は、`tolerant` に至るまでの途中段階（検証用）です。

## 結果の見方（本番で人が確認するとき）

本番環境で `run` を実行したあと、次で件数と理由の分布だけを出せます。画像・ファイル名は出ません。

```bash
python -m donor_mask aggregate --logs ./out --mode run
```

出るもの: ok / review の件数と ok 率、review の理由コード別の件数、解像度などの分布。共有するのは、この集計だけにしてください。

主な review の理由:

| 理由コード | 意味 | 対処 |
| --- | --- | --- |
| `C_NO_CARD` / `C_TOUCHES_BORDER` | カードの四辺が取れない・端で欠けている | 余白をつけて撮り直し |
| `Q_LOW_RES` / `Q_BLUR` / `Q_GLARE` | 小さい・ぼけ・光の反射 | 撮り直し |
| `O_*` | 表面・別のカード・鏡像・向きが決まらない | 画像を目で確認 |
| `F_*` / `M_*` | 塗る欄が確実に特定できない・手書きがはみ出している | 画像を目で確認 |
| `V_*` | 塗った後の自動検証で不合格 | 画像を目で確認 |

全コードの一覧と意味は [docs/REFERENCE.md](docs/REFERENCE.md) にあります。

## 他のコマンド

| コマンド | 用途 |
| --- | --- |
| `python -m donor_mask run --diagnostic --in ./inbox --out ./diag` | どの段で落ちたかを全段分記録する（調査用。画像は出ない） |
| `python -m donor_mask run --shadow ...` | ok 相当でも `ok/` に出さず、全件 review にして提案だけ見る（試運転用） |
| `python -m donor_mask verify --orig <原本> --masked <ok の png> --log <ログ>` | 塗った結果を、別の経路でもう一度検証する |
| `python tools/eval_variations.py` | 背景・傾き・縮小・ブレを自動生成して、ok 率と誤検出を数える（合成画像のみ） |
| `pytest -q` | テスト（合成データのみ。オフライン。約 3 分） |

## 使うときの注意

- **対象は免許証の裏面だけ**です。マイナンバーカードは対象外で、個人番号が写るため別途受領ルールの確認が必要です。
- `out/review/` は欄の中身が見える画像です。アクセス制限と保存期間は運用側で決めてください。
- 設定ファイルの値は、手元 9 枚で決めた暫定値です。実写真の分布を見て見直す前提です。
